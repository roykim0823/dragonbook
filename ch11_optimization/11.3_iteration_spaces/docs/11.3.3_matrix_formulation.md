# §11.3.3 Matrix Formulation of Inequalities

Part of [11.3 Iteration Spaces](../README.md) · previous: [§11.3.2](11.3.2_execution_order.md) · next: [§11.3.4](11.3.4_symbolic_constants.md)

**Matrix form `Bx + b ≥ 0`** (Eq. (11.1); the book works this example as Example 11.8, Fig. 11.13). Write every inequality in the standard shape **`(coefficients)·x + constant ≥ 0`**. There are only two rewriting moves, and only one rule to remember:

* move everything to the left side;
* if you multiply by a negative number, **flip** the inequality.

Doing that to the four inequalities of Fig. 11.10:

```
 i ≥ 0        →   i          ≥ 0   →  ( 1)i + ( 0)j + 0 ≥ 0
 i ≤ 5        →  −i + 5      ≥ 0   →  (−1)i + ( 0)j + 5 ≥ 0      (multiplied by −1: ≤ became ≥)
 j ≥ i        →  −i + j      ≥ 0   →  (−1)i + ( 1)j + 0 ≥ 0
 j ≤ 7        →  −j + 7      ≥ 0   →  ( 0)i + (−1)j + 7 ≥ 0
```

Each line now has the shape `u·i + v·j + w ≥ 0`. Stack the coefficient pairs `[u, v]` as the rows of a matrix `B` and the constants `w` as the entries of a vector `b`, and the four inequalities become one matrix-vector inequality. That is the book's Fig. 11.13 (Example 11.8):

**Figure 11.13: Matrix-vector multiplication and a vector inequality represents the inequalities defining an iteration space**
```
    ┌  1   0 ┐           ┌ 0 ┐     ┌ 0 ┐
    │ −1   0 │   ┌ i ┐   │ 5 │     │ 0 │
    │ −1   1 │ · └ j ┘ + │ 0 │  ≥  │ 0 │
    └  0  −1 ┘           └ 7 ┘     └ 0 ┘
        B         x        b
```

Row 1 of the product is `i ≥ 0`, row 2 is `−i + 5 ≥ 0`, row 3 is `−i + j ≥ 0`, row 4 is `−j + 7 ≥ 0`: the same four lines as above, read back. In this notation the iteration space is `{ (i, j) ∈ Z² | B·(i, j) + b ≥ 0 }`, which is Eq. (11.1).

Two facts you will use constantly. Both come from reading a row as an inequality *about one variable* and solving for it.

**Fact 1: the sign of a variable's coefficient tells you which kind of bound the row is.** Take any row and pick a variable `v`. Move every other term to the right-hand side; call that right-hand side the *rest*. If the coefficient of `v` is positive, the row says `v ≥ something`, a **lower bound**. If it is negative, dividing by it flips the inequality, so the row says `v ≤ something`, an **upper bound**. If it is zero, the row says nothing about `v`.

Doing this for each of the four rows of Fig. 11.10, first for `i`, then for `j`:

```
 row                 solve for i                       solve for j
 ──────────────────  ────────────────────────────────  ────────────────────────────────
 ( 1)i + ( 0)j + 0   i ≥ 0            coef +1 → LOWER  coef 0 → says nothing about j
 (−1)i + ( 0)j + 5   −i ≥ −5 → i ≤ 5  coef −1 → UPPER  coef 0 → says nothing about j
 (−1)i + ( 1)j + 0   −i ≥ −j → i ≤ j  coef −1 → UPPER  j ≥ i            coef +1 → LOWER
 ( 0)i + (−1)j + 7   coef 0 → says nothing about i     −j ≥ −7 → j ≤ 7  coef −1 → UPPER
```

So the same row `−i + j ≥ 0` is an *upper* bound when you are asking about `i` (`i ≤ j`) and a *lower* bound when you are asking about `j` (`j ≥ i`). Which one it is depends on which variable you are solving for, not on the row. This sort by sign is the first thing done when loop bounds are derived from the rows in [§11.3.5](11.3.5_controlling_execution_order.md).

**Fact 2: with a coefficient of ±1 the bound is just the rest.** Every row in this section has coefficients 0 or ±1, so once the row is solved for `v` the bound is the right-hand side as it stands. Other coefficients need a division; they are handled in *Integers vs. rationals* in [§11.3.5](11.3.5_controlling_execution_order.md).

## Code example 02 — `./run.sh 2`

Program 02 builds this polyhedron row by row with `addInequality` (each call is one inequality, written as `coefficients, constant`), prints the rows, and counts the integer points two ways: by running the loop nest of Fig. 11.10 and by brute-force enumeration of the polyhedron. Both must give 33, which is the first check that the loop and the inequalities describe the same set. The brute force, `enumerateBox(poly, lo, hi)`, tries every integer point of the square `[lo, hi]²` and keeps those that satisfy all four rows, so `lo` and `hi` only have to enclose the polyhedron; `−2` and `12` are nothing more than a generous guess around `0..5 × 0..7`. Because a box that is too small would silently undercount, the program also enumerates a much larger box and checks that it finds nothing new. Every later program that calls `enumerateBox` uses a box chosen the same way.

The two types the program is built from, `Constraint` and `Polyhedron` with its `addInequality` and `column`, are quoted and explained in [the code bundle](code_bundle.md#polyh).

Where each line of the output comes from (the printing functions are quoted in [the code bundle](code_bundle.md#polyh)):

| line(s) of `./run.sh 2` | printed by |
|---|---|
| `Example 11.8: B i + b >= 0 for Fig. 11.10  (vars: i j )` | `printRows`: the title, then the variable names |
| the four indented `… >= 0` rows | `printRows` → `rowStr` → `exprStr` (and `signStr` for each sign) |
| `Fig. 11.10 original nest: 33 iterations` and the two lines after it | the program's own `std::cout` statements |

**code/src/02_example_11_8_matrix_form.cpp**
```cpp
#include "enumerate.h"

int main() {
  Polyhedron poly; // Fig. 11.10:  for (i=0;i<=5;i++) for (j=i;j<=7;j++)
  poly.vars = {"i", "j"};
  // Each call appends one row  coefficients . (i, j) + constant >= 0:
  //    i     >= 0   (i >= 0)   poly.rows[0]: a = [ 1,  0]  c = 0
  //   -i + 5 >= 0   (i <= 5)   poly.rows[1]: a = [-1,  0]  c = 5
  //   -i + j >= 0   (j >= i)   poly.rows[2]: a = [-1,  1]  c = 0
  //   -j + 7 >= 0   (j <= 7)   poly.rows[3]: a = [ 0, -1]  c = 7
  poly.addInequality({{"i", 1}}, 0)
      .addInequality({{"i", -1}}, 5)
      .addInequality({{"i", -1}, {"j", 1}}, 0)
      .addInequality({{"j", -1}}, 7);
  printRows(poly, "Example 11.8: B i + b >= 0 for Fig. 11.10");

  long byLoop = 0; // count the iterations by running the nest
  for (long i = 0; i <= 5; i++)
    for (long j = i; j <= 7; j++)
      byLoop++;

  // enumerateBox tries every integer point of the square [lo, hi]^2 and keeps
  // those that satisfy all four rows, so the box only has to CONTAIN the
  // polyhedron: 0 <= i <= 5 and 0 <= j <= 7 fit inside [-2, 12]^2 with room to
  // spare. A box that is too small would silently undercount, so also check
  // that a much bigger box finds nothing new.
  size_t byPoly = enumerateBox(poly, -2, 12).size();
  size_t byBiggerBox = enumerateBox(poly, -20, 30).size();
  std::cout << "Fig. 11.10 original nest: " << byLoop << " iterations\n";
  std::cout << "integer points of the polyhedron (brute force): " << byPoly
            << "  " << ((long)byPoly == byLoop ? "== loop nest" : "MISMATCH")
            << "\n";
  std::cout << "box check: [-2,12]^2 gives " << byPoly << ", [-20,30]^2 gives "
            << byBiggerBox << "  "
            << (byBiggerBox == byPoly ? "(same: the box is big enough)"
                                      : "MISMATCH")
            << "\n";
}
```

`enumerateBox` and the three helpers above it are quoted and explained in [the code bundle](code_bundle.md#enumerateh); it is the ground truth that every later verification rests on, and it needs nothing beyond poly.h.
